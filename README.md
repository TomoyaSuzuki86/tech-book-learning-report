# 継続的な技術学習とアウトプットの記録

このリポジトリは、自身の技術学習を体系的に記録し、アウトプットを通じて知識の定着を図ることを目的とした個人リポジトリである。年間を通じて四半期ごとに1冊の技術書を読み、その学習内容をここに集約する。

## 🎯 目標

**四半期毎に1冊の技術書を読み、内容を自分のブログやGitHubにまとめ、実践的な知識として定着させる。**  
**理由**: 技術書を単に読むだけでなく、内容をアウトプットすることで知識の定着率を高め、実務での応用力向上を目指す。継続的な学習習慣を身につけ、技術の変化に対応できるエンジニアになることを目指す。

## 📝 記載フォーマット

### 1. ファイル名ルール

- ファイル名は、書籍の章番号と章タイトルを組み合わせた形式とする。
  - 例: `XX_章タイトル.md`（XXは2桁の数字）
- 日本語のファイル名は、スペースの代わりにアンダースコア `_` を使用する。
- 長すぎる場合は、意味が通じる範囲で省略または要約する。

### 2. ファイル冒頭のメタ情報

各ファイルの冒頭には、以下のメタ情報を必ず記載する。

```markdown
---
title: "[書籍の章番号] [書籍の章タイトル]"
book_title: "ドメイン駆動設計 モデリング/実装ガイド"
author: "松岡 幸一郎"
date: 2025-06-04 # 記述した日付
tags: [DDD, コアコンセプト, SES] # 関連するタグを3つ程度記載 (必須)
---
```

- `title`: そのファイルの主題となる書籍の章タイトルを正確に記述する。
- `book_title`: 書籍のタイトルを正確に記述する。
- `author`: 書籍の著者名を正確に記述する。
- `date`: Markdownファイルを記述した日付を `YYYY-MM-DD` 形式で記載する。
- `tags`: そのファイルの主要な内容を表すタグを、カンマ区切りで3つ程度（最低1つ）記載する。

### 3. セクション構成

ファイル冒頭のメタ情報の直後から、以下のセクション構成を厳守する。

```markdown
# [書籍の章番号] [書籍の章タイトル]

## 💡 主要な学びのポイント (Key Learning Points)

- **[学びのポイント1を箇条書きで簡潔に]**
    - 例: DDDでは言葉の定義が重要であり、DDD Referenceを正とする。
- **[学びのポイント2を箇条書きで簡潔に]**
    - 例: モデルとは問題解決のために物事の特定の側面を抽象化したものである。
- ... (章全体から重要なポイントを5〜10個程度箇条書きで抽出)

## 🎯 SESエンジニアとしての学びと活用 (Learnings & Application for SES Engineers)

この章から得られた学びは、SESエンジニアとして以下の点で活用できると考える。

### [活かせる具体的な場面1]

[その学びがSESエンジニアとして、どのような具体的な場面で役立つのかを詳細に記述する。例えば、顧客との要件定義、チーム内のコミュニケーション、設計レビュー、技術提案など。なぜ役立つのか、どのような効果が期待できるのかも記述する。5行〜10行程度。]

### [活かせる具体的な場面2]

[別の具体的な場面について記述。同様に記述。]
```

### 4. 記述ルールとスタイルガイド

- **言葉遣い**: 常体（〜である、〜だ）を使用する。
- **客観性**: 書籍の内容を基にし、個人的な解釈は「SESエンジニアとしての学びと活用」セクションに限定する。
- **簡潔性**: 各セクションの記述は簡潔にまとめ、冗長な表現を避ける。
- **強調**: 重要なキーワードや概念は、`**太字**` で強調する。
- **コードブロック**: コード例は必ずバッククォート3つで囲み、言語を指定する（例: ```java）。
- **箇条書き**: 項目を列挙する際は、ハイフン `-` を使用した箇条書きを推奨する。
- **見出しレベル**: `#` から始まる見出しは、セクション構成で定められたレベルを厳守する。
